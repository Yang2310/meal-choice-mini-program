# 这顿有解｜美食记录与随机选餐小程序

**一个核心功能已可用、尚未正式发布的微信小程序全栈项目：管理个人美食库，并从菜品、店铺或家常菜中随机决定下一餐。**

**项目角色：** 独立全栈开发，负责产品流程、数据模型、API 集成、图片安全、测试和部署准备。  
**技术栈：** 微信小程序 · JavaScript · Node.js / Fastify · MySQL · 腾讯云 COS · 微信开放接口 · Docker / Nginx  
**发布状态：** **手动录入等核心业务已开发完成、能正常使用；小程序尚未公开上线。** 本仓库不提供持续在线的公开 Demo。

## 项目要解决什么问题

记录日常吃过、想吃、做过和准备做的食物，并在不知道下一顿吃什么时，从自己的美食库筛选候选、随机抽取结果。

产品分成两种模式：

- **外面吃：** 管理店铺与菜品，查看店铺详情和评分，按店铺或菜品浏览、搜索与筛选；可以随机**抽菜品，也可以随机抽店铺**。
- **自己烧：** 记录做过或想做的菜，使用自己的分类、条件和抽选逻辑，避免与外食数据混在一起。

**现有功能通过手动录入就可以正常使用。** 目前体验上的主要问题是：一次记录店铺名称、地址和多道菜需要填不少字段。因此考虑未来增加“截图识别并预填表单”，但该功能**尚未开发，暂时没有确定的开发时间**。

## 系统架构

微信小程序通过业务 Service、Repository 与 MediaService 抽象访问数据和媒体，业务页面不直接耦合云端实现。

```text
微信小程序 (JavaScript / WXML / WXSS)
  ├─ 页面：录入 / 美食库 / 店铺详情 / 随机抽选
  ├─ 业务服务、Repository、MediaService
  └─ 经授权的 HTTPS / REST 请求
                    │
                    ▼
Node.js / Fastify 后端 (/api/v1)
  ├─ 微信身份 / Session / 用户权限
  ├─ 店铺、菜品、类型、筛选与抽选
  ├─ MySQL 事务与版本迁移
  ├─ 腾讯 COS 私有图片生命周期
  └─ 微信身份与内容安全接口
```

本地模式、小程序与本机 API/MySQL 联调、真实微信身份接入、真实 COS 图片接入和生产环境有明确配置边界。生产方案使用 Docker/Nginx/HTTPS 与托管 MySQL，但正式上线验收单独进行。

## 体现的工程能力

**1. 数据建模与一致性。** 店铺、菜品和店铺类型分别建模，保留用户归属。一个店铺可以在单次事务中新增多道菜；匹配已有店铺时，不会静默覆盖有冲突的非空地址。

**2. 独立的抽选业务。** 抽店铺根据店铺类型过滤候选，并支持本轮已抽结果排除；外食菜品与自己烧采用独立候选池和条件，不把抽选逻辑依赖于动画实现。

**3. 私有图片访问控制。** 小程序预处理图片，后端检查文件 MIME 和真实文件签名、对象命名空间与用户权限；图片存入腾讯 COS 私有桶，详情页按需获取短期签名链接，列表页避免额外生成图片链接。

**4. 跨数据库与对象存储的失败处理。** MySQL 和 COS 无法构成同一个原子事务，因此创建失败时需要回滚已上传图片；删除操作区分数据库成功、媒体清理部分失败和操作失败，避免向用户误报结果。

**5. 集成与测试。** 项目使用真实微信身份/文字安全接口、真实 COS 的本地联调，配置可切换的基础设施适配，配备前后端自动化测试、API 冒烟测试与容器部署结构。微信**图片安全审核**的异步提交和回调处理代码已具备，但真实生产 HTTPS 回调尚未完成验收。

## 未来考虑：上传截图，自动预填录入表单

**尚未开发；没有确定完成时间；不是现有手动录入流程能够使用的前提。**

目标是让用户上传**点单、外卖、团购、闪购等页面截图**，从截图中提取确实存在的客观信息，例如：

- 店铺名称，以及截图中明确提供的地址；
- 已点或已购买的菜品/商品、数量和价格；
- 截图里有明确内容的套餐及组合信息。

提取结果用于**自动填写可编辑表单**，由用户检查、补全、确认后再保存。不能凭空补全缺失地址，也不应自动编造主观评分、店铺类型或菜品评价。

注意：这指的是**订单/页面截图理解**，不是对食物照片本身进行菜品识别；同时也和检查图片是否合法的**微信图片内容安全审核**完全不同。

## 当前项目状态

**现有核心功能：** 手动录入、店铺管理与店铺类型、个人美食库、三种抽选路径、用户隔离和图片处理等已经实现并可使用。私有项目文档还记录了后端生产部署和冒烟测试。

**尚未正式发布：** 微信小程序没有公开上架；生产环境、合法域名、真机与版本发布等剩余验收须与后端代码和单项测试区别看待。截图辅助录入因提升便利性而规划，并非底层美食库与抽选功能的必要依赖。

这是公开技术作品集，不提供完整私有源码、真实用户数据、密钥及生产环境私有配置。
